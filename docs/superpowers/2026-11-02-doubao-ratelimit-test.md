# 豆包合成接口限流实测记录（2026-11-02）

## 目的

回答：频繁请求豆包合成接口是否会被服务端限流/封禁？阈值大约是多少？

## 测试方法

新增 `tts/doubao_ratelimit_test.go`（`TestDoubaoRateLimit`），默认跳过，仅 `DOUBAO_RATE_TEST=1` 时真连豆包。

- **突发档位**：每档并发 N 个请求同时发出，全部成功才进入下一档。
  - 档位可用 `DOUBAO_RATE_TEST_LEVELS` 指定（CSV）。
- **持续压力**：固定并发 N 连续请求 10 秒，记录成功/失败与实际 RPS。
  - 可用 `DOUBAO_RATE_TEST_SUSTAIN` 指定（CSV）。
- **保护策略**：任一档出现失败立即停止后续档位，并输出首个错误原文。
- 每轮开始前预热一次，排除首次建连/缓存冷启动干扰。
- 统一使用短文本「限流测试短句。」。

## 环境

- 本机（Linux），Go 1.x，`CGO_ENABLED=0`
- Cookie：`~/.config/edgetts-speechd/doubao.json`（Edge 提取缓存，2221 字节）
- 端点：`wss://frontier-audio-web-ws.doubao.com/api/v2/sami/voicegenie`
- 出口：本机默认网络（IPv6/IPv4 由 Go Happy Eyeballs 选择）

|---|---|---|---|---|
| 1 | 1/1 | 1.034s | 1.0 | 0 |
| 2 | 2/2 | 1.105s | 1.8 | 0 |
| 4 | 4/4 | 1.084s | 3.7 | 0 |
| 8 | 8/8 | 1.057s | 7.6 | 0 |
| 16 | 16/16 | 1.134s | 14.1 | 0 |
| 32 | 32/32 | 1.182s | 27.1 | 0 |
| 64 | 64/64 | 1.468s | 43.6 | 0 |
| 128 | 128/128 | 2.433s | 52.6 | 0 |

预热耗时分别为 1.06s / 1.05s / 1.12s / 0.93s / 0.97s（均为热态）。

### 持续压力（固定并发连续 10 秒）

| 并发 | 成功次数 | 失败 | 实际 RPS |
|---|---|---|---|
| 8 | 86 | 0 | 7.9 |
| 16 | 190 | 0 | 17.5 |
| 32 | 372 | 0 | 34.3 |
| 64 | 701 | 0 | 64.1 |

## 结论

**在本次实测范围内未观察到任何限流或封禁。**

- 突发最高测到 **128 并发，约 52.6 req/s**，100% 成功。
- 持续最高测到 **64 并发连续 10 秒，701 次请求，约 64.1 req/s**，0 失败。
- 各轮测试累计发出 **2000+ 次**真实合成请求（含预热与多轮重复），期间及之后均未出现鉴权失败、状态码错误、连接被拒或空音频。

因此：**本次未测得频率上限**；服务端的实际阈值高于上述压力（或限流维度不在本机这一账号/IP 上）。

## 局限（不得外推）

1. 仅测同一账号 Cookie、同一出口 IP。
2. 仅测短文本；未测超长文本（单次 4096 字节上限）与超长持续（>10s）。
3. 未覆盖跨分钟/跨小时的累计窗口（若有日配额，本测试无法发现）。
4. 结论只描述本次实测，**不代表服务端正式配额或 SLA**。

## 复测命令

```bash
# 默认阶梯（1→32）
DOUBAO_RATE_TEST=1 go test ./tts/ -run TestDoubaoRateLimit -count=1 -v

# 指定突发档位
DOUBAO_RATE_TEST=1 DOUBAO_RATE_TEST_LEVELS=64,128 \
  go test ./tts/ -run TestDoubaoRateLimit -count=1 -v

# 持续压力（并发 16、32 各 10 秒）
DOUBAO_RATE_TEST=1 DOUBAO_RATE_TEST_LEVELS=1 DOUBAO_RATE_TEST_SUSTAIN=16,32 \
  go test ./tts/ -run TestDoubaoRateLimit -count=1 -v
```
